# План релиза на 8 недель

tags: #ponchi #release #8weeks
updated: 2026-04-16

## Принцип

Каждая неделя должна заканчивать кусок продукта, а не просто “движение по задачам”.

Правило недели:

- сначала стабилизировать модель;
- потом стабилизировать service / view model;
- потом довести UI;
- потом провести ручную проверку;
- потом записать итоги в заметку.

## Неделя 1 — сборка, конфиг, гигиена репозитория

Фокус:

- workspace / pods / build settings;
- bundle id / deployment target / orientations;
- `AppConfig` и `Info.plist`;
- чистка репозитория как рабочей среды.

Сделать:

- довести `PonchiApp.swift` до полного использования `AppConfig`;
- убрать хардкод `menuURL` и map key;
- исправить `PONCHI_MENU_URL` в `Release`;
- принять решение по `Ponchi-clean`;
- добавить ignore для function zip архивов;
- проверить Xcode build локально через `Ponchi.xcworkspace`.

Результат недели:

- проект стабильно собирается;
- конфиг читается из одного понятного места;
- репозиторий перестает путать тебя дубликатами и архивами.

## Неделя 2 — модели и корзина

Фокус:

- `Ponchi`;
- `Cart`;
- `Order`;
- базовая доменная консистентность.

Сделать:

- починить `id` и `Equatable`;
- добавить `comment` в модель;
- исправить `teaType` flow;
- определить финальную форму `Order`;
- убрать двойную логику бонусов.

Результат недели:

- корзина ведет себя корректно;
- товарная конфигурация не теряется;
- доменная модель перестает зависеть от UI-костылей.

## Неделя 3 — auth-клиент

Фокус:

- `UserViewModel`;
- auth forms;
- session restore;
- ошибки и loading state.

Сделать:

- ввести единый auth state machine;
- добавить disable / loading / error presentation;
- сделать `reset password` UI;
- привести auth copy и UX в последовательный flow;
- проверить restore session и logout.

Результат недели:

- auth на клиенте ощущается как готовый продуктовый сценарий.

## Неделя 4 — auth-backend

Фокус:

- `ponchi-functions`;
- gateway;
- sessions;
- SMS.

Сделать:

- подключить SMS provider;
- ввести rate limit;
- добавить refresh / revoke / logout;
- спроектировать delete account endpoint;
- провести smoke-test auth flow через `curl` и реальный клиент.

Результат недели:

- auth становится настоящим backend flow, а не имитацией.

## Неделя 5 — реальные заказы

Фокус:

- `OrderService`;
- `OrderViewModel`;
- `PonchiCartView`;
- `PonchiChequeView`;
- backend endpoints `/orders`.

Сделать:

- описать order DTO;
- реализовать create/list orders;
- заменить локальное оформление заказа на async backend flow;
- отрисовать статусы, loading, empty, retry;
- очистку корзины делать только после server success.

Результат недели:

- пользователь может реально оформить заказ и увидеть его после перезапуска приложения.

## Неделя 6 — локальное хранение и устойчивость

Фокус:

- `SwiftData` для локального слоя;
- menu cache;
- favorites;
- draft cart;
- классификация сетевых ошибок.

Сделать:

- определить source of truth table;
- ввести cache последнего меню;
- перенести favorites в локальное хранение;
- при необходимости сохранить черновик корзины;
- улучшить network error layer.

Результат недели:

- приложение становится устойчивее к офлайну и повторным запускам.

## Неделя 7 — UI polish

Фокус:

- профиль;
- заказы;
- auth UX;
- адаптивность;
- accessibility.

Сделать:

- завершить профиль;
- усилить экран заказов;
- пройтись по пустым состояниям;
- пересчитать menu grid;
- сделать базовый accessibility pass;
- привести UI к более цельному релизному уровню.

Результат недели:

- сильные и слабые зоны UI выравниваются.

## Неделя 8 — QA, TestFlight, App Store

Фокус:

- тесты;
- crash reporting;
- privacy/legal;
- metadata;
- финальный smoke test.

Сделать:

- unit + UI smoke tests;
- crash monitoring;
- privacy policy / support URL / app privacy;
- delete account entry point;
- screenshots;
- export compliance;
- TestFlight build;
- ручной прогон на чистой установке.

Результат недели:

- у тебя есть не только приложение, но и пакет, который можно реально отправлять в TestFlight / App Store.

## Риски по неделям

- Неделя 4 может растянуться из-за SMS/provider/backend.
- Неделя 5 может растянуться из-за orders contract.
- Неделя 8 часто оказывается недооцененной, если legal/privacy оставить “на потом”.

## Что можно вырезать, если сроки начинают гореть

- сложные бонусы;
- расширенные промо-механики;
- iPad polish;
- глубокую аналитику;
- второстепенные визуальные фишки, не влияющие на core flow.

## Критерий успеха 8-недельного плана

- core flow работает от первого запуска до заказа;
- релизная сборка предсказуема;
- нет грубых противоречий между клиентом, backend и документацией;
- App Store пакет готов не только технически, но и операционно.
