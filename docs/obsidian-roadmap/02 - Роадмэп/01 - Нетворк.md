# Нетворк

tags: #ponchi #roadmap #network #backend
updated: 2026-04-16

## Текущее состояние

Что уже есть:

- `NetworkService`
- `AuthService`
- `SessionManager`
- `LoadMenuUseCase -> Repository -> DataSource`
- serverless auth-функции в `ponchi-functions`

Что еще не закончено:

- конфиг до конца не вынесен из кода;
- `menu` еще живет на публичном JSON;
- `orders` backend отсутствует;
- `auth` без SMS-провайдера, refresh, revoke и delete account;
- нет error classification, retry/backoff и observability.

## Целевое состояние к релизу

- `Debug`, `Release` и желательно `Staging` читают env-значения из конфигурации.
- Меню приходит из настоящего API, а не из bucket JSON.
- Заказы создаются и читаются только через backend.
- Auth покрывает весь жизненный цикл сессии.
- Сетевой слой различает transport/server/auth/decoding ошибки.
- Есть минимум crash reporting и логирование ключевых фейлов.

## P0

### 1. Завершить конфигурационный слой

Что сделать:

- перевести `PonchiApp.swift` на `AppConfig.menuURL`;
- убрать хардкод карты и использовать `AppConfig.yandexMapsAPIKey`;
- добавить `YandexMapsAPIKey` в `Info.plist`;
- вычистить hardcoded URL из `PreviewFactory`;
- проверить и исправить `PONCHI_MENU_URL` в `Release`.

Файлы:

- `Ponchi/PonchiApp.swift`
- `Ponchi/Utilites/Configs/AppConfig.swift`
- `Ponchi/Utilites/Preview/PreviewFactory.swift`
- `Ponchi/Info.plist`
- `Ponchi.xcodeproj/project.pbxproj`

Definition of done:

- в основном target не осталось захардкоженных URL и API key;
- `AppConfig` реально используется всеми runtime-конфигами;
- `Debug` и `Release` поднимаются на своих значениях.

### 2. Перевести меню с JSON на API

Что сделать:

- договориться о формате `/v1/menu`;
- сделать DTO под backend ответ;
- адаптировать `MenuRemoteDataSource` к API-формату;
- оставить локальный JSON только как аварийный fallback.

Файлы:

- `docs/api/contract.md`
- `Ponchi/Utilites/Network/MenuData/MenuRemoteDataSource.swift`
- `Ponchi/Utilites/Network/MenuData/Repository.swift`
- `Ponchi/Utilites/Network/MenuData/LocalMenuService.swift`
- будущий backend endpoint `/v1/menu`

Definition of done:

- меню грузится с backend;
- офлайн-фоллбек остается, но не является основной боевой стратегией.

### 3. Закрыть production auth

Что сделать:

- подключить реальную SMS-отправку;
- добавить rate limiting и `retry_after`;
- ввести `refresh token`;
- добавить logout/revoke endpoint;
- спроектировать delete account endpoint;
- продумать сессионную модель и сроки жизни токенов.

Файлы:

- `ponchi-functions/auth-request-code/index.js`
- `ponchi-functions/auth-login/index.js`
- `ponchi-functions/auth-me/index.js`
- `ponchi-functions/auth-reset-password/index.js`
- `ponchi-functions/auth-verify-code/index.js`
- `Ponchi/Utilites/Network/UserData/AuthService.swift`
- `Ponchi/Utilites/Network/UserData/SessionManager.swift`

Definition of done:

- пользователь может пройти `signup`, `verify`, `login`, `restore`, `logout`, `reset password`;
- сервер ограничивает запросы кода;
- access token можно обновить или отозвать.

### 4. Реализовать orders API

Что сделать:

- описать DTO создания заказа и ответа сервера;
- завести клиентский `OrderService`;
- поднять `POST /v1/orders` и `GET /v1/orders`;
- учесть `PRICE_MISMATCH`, availability, snapshot items.

Definition of done:

- заказ создается сервером;
- статус и история читаются с сервера;
- клиент больше не полагается на локальные массивы как источник истины.

## P1

### 1. Улучшить `NetworkService`

Что сделать:

- выделить request builder;
- различать `no internet`, `timeout`, `401`, `403`, `404`, `409`, `429`, `5xx`;
- добавить единый способ парсинга error payload;
- продумать retry/backoff для безопасных запросов;
- добавить debug logging.

### 2. Ввести локальный cache последнего успешного меню

Что сделать:

- сохранять последний успешный remote snapshot;
- при ошибке сети сначала читать кеш, потом bundle fallback;
- в UI показывать, что данные офлайн/старые.

### 3. Подготовить observability

Что сделать:

- crash reporting;
- auth funnel;
- order create success/failure;
- menu load source: remote / cache / bundle;
- карта открылась / карта недоступна.

## P2
