# Бизнес-логика

tags: #ponchi #roadmap #domain #models #viewmodels
updated: 2026-04-16

## Текущее состояние

Сильные стороны:

- есть понятные доменные сущности `Ponchi`, `User`, `Order`;
- есть `Cart`, `PonchiViewModel`, `UserViewModel`, `OrderViewModel`;
- часть flow уже собрана и работает как прототип.

Слабые стороны:

- доменные сущности не полностью отражают пользовательские сценарии;
- `ViewModel`-слой держит слишком много несвязанных обязанностей;
- часть UI-state живет рядом с серверной логикой;
- заказы и бонусы до сих пор в полу-локальном режиме.

## Целевое состояние к релизу

- у каждого сценария один источник истины;
- модели содержат только нужные поля;
- `ViewModel`-ы меньше и ответственнее;
- корзина и заказ опираются на доменную модель, а не на UI-костыли;
- server truth для user/orders, local truth для cache/drafts/favorites.

## P0

### 1. Починить идентичность товара

Проблема:

- `Ponchi.id` и `Equatable` не учитывают `selectedTeaType`;
- `comment` вообще не участвует в идентичности;
- это ломает корзину для разных вариантов одного товара.

Что сделать:

- включить `selectedTeaType` в `id`;
- решить, должен ли `comment` участвовать в `id`;
- синхронизировать `Cart.addItem(_:)` с новой логикой.

Файлы:

- `Ponchi/Models/Ponchi.swift`
- `Ponchi/ViewModels/Cart.swift`

### 2. Встроить `comment` в доменную модель

Проблема:

- `comment` есть в `PonchiViewModel`, но не в `Ponchi`, `Cart`, `Order`.

Что сделать:

- добавить `comment` в `Ponchi`;
- при `addNewItem` и `saveChanges` сохранять comment в модель;
- отобразить comment в корзине и использовать при создании заказа.

Файлы:

- `Ponchi/Models/Ponchi.swift`
- `Ponchi/ViewModels/PonchiViewModel.swift`
- `Ponchi/ViewModels/Cart.swift`
- `Ponchi/Models/Order.swift`
- `Ponchi/Views/Screens/CartViews/Components/PonchiListCell.swift`

### 3. Починить tea flow

Проблема:

- `hasTeaType` зависит от `selectedTeaType`, а не от `teaType`;
- в `Ponchi.json` есть товары с `teaType`, но без `selectedTeaType`.

Что сделать:

- проверять `teaType?.isEmpty == false`;
- при выборе продукта инициализировать `selectedTeaType` первым доступным значением;
- проверить отображение названия и картинки для чайных позиций.

Файлы:

- `Ponchi/ViewModels/PonchiViewModel.swift`
- `Ponchi/Models/Ponchi.swift`
- `Ponchi/Views/Screens/DetailViews/PonchiDrinkDetailView.swift`
- `Ponchi/Resources/Ponchi.json`

### 4. Убрать двойной источник истины для бонусов

Проблема:

- есть и `user.bonuses`, и `bonusPoints`;
- header, profile и бонусный UI читают разные значения.

Что сделать:

- оставить один источник истины;
- лучше всего оставить `user.bonuses` как доменную цифру;
- `bonusPoints` удалить или превратить в computed wrapper;
- `PonchiBonusView` либо интегрировать, либо удалить.

Файлы:

- `Ponchi/ViewModels/UserViewModel.swift`
- `Ponchi/Views/Screens/ProfileViews/Components/PonchiHeaderMenu.swift`
- `Ponchi/Views/Screens/DetailViews/Main/PonchiBonusView.swift`

### 5. Перевести `Order` в реальную доменную сущность

Сейчас:

- `Order` содержит только `items`, `status`, `date`;
- серверных идентификаторов и snapshot-полей нет.

Что нужно к релизу:

- `serverId`
- `createdAt`
- `pickupTime`
- `status`
- `comment`
- `item snapshots`
- `server total`

Файлы:

- `Ponchi/Models/Order.swift`
- `Ponchi/ViewModels/OrderViewModel.swift`
- `docs/api/contract.md`

## P1

### 1. Разделить `UserViewModel`

Предлагаемое направление:

- `AuthViewModel`
- `ProfileViewModel`
- `FavoritesStore` или `FavoritesViewModel`

Сейчас не обязательно сразу разносить по файлам, но нужно хотя бы логически разделить обязанности.

### 2. Разделить `PonchiViewModel`

Предлагаемое направление:

- `MenuViewModel`
- `ProductDetailViewModel`
- `MenuScreenState`

Сейчас:

- menu loading;
- selected category;
- detail customization;
- comment;
- offline banner;
- cart edit flow.

Это уже слишком много для одного объекта.

### 3. Определить source of truth

Целевая таблица:

- `session` -> `Keychain`
- `profile` -> backend
- `orders` -> backend
- `favorites` -> local persistence
- `menu` -> backend + cached snapshot
- `draft cart` -> local persistence

### 4. Довести локальное хранение

Направление:

- `SwiftData` для favorites / cache / draft cart;
- `Keychain` для токенов;
- `UserDefaults` только для мелкого UI-state вроде последней категории.

## Definition of done для бизнес-логики

- корзина предсказуемо различает разные товарные конфигурации;
- комментарий не теряется;
- бонусы везде совпадают;
- заказ воспроизводим после перезапуска;
- каждый `ViewModel` можно объяснить в одном абзаце без фразы “он делает почти все”.
