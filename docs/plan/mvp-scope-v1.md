# Ponchi v1 — MVP scope freeze (Draft)

Дата: 2026-03-10

## 1) Текущее состояние кода (короткий аудит)

### Уже есть
- Меню: загрузка из сети (JSON) с офлайн‑фоллбеком на локальный JSON; категории, поиск, детали товара, размеры, топпинги, апселл.
- Корзина: добавление, изменение количества, удаление, очистка, расчет суммы.
- Заказы: локальное создание заказа из корзины, список активных/завершенных заказов.
- Профиль: локальные данные пользователя, избранное, редактирование профиля, выход.
- UI‑оболочка: таббар, экраны меню/корзины/заказов/профиля, карта (YandexMapView).

### Чего нет / имитация
- Реальная аутентификация по телефону (сейчас локальная имитация + Keychain).
- Backend‑сессии, refresh, ошибки auth.
- Реальные заказы на бэке, статусы из сервера.
- Админка для меню/промо (сейчас меню в JSON).
- Политики/юридические экраны, удаление аккаунта.

Источник: `Ponchi/ViewModels/*`, `Ponchi/Views/Screens/*`, `Ponchi/Utilites/Network/*`.

## 2) MVP v1 (заморозка scope)

### Must‑have (в релиз v1)
1. Меню: список, категории, поиск, деталка товара, размеры, топпинги.
2. Корзина: добавление/удаление/изменение количества, итоговая сумма.
3. Базовый заказ: оформление заказа, экран статуса/истории (минимум: «В работе/Завершён»).
4. Профиль: базовые данные пользователя.
5. Auth по телефону через сторонний сервис + SMS OTP, session refresh.
6. Ошибки и пустые состояния, офлайн‑фоллбек меню.
7. Удаление аккаунта внутри приложения (App Store requirement).

### Should‑have (если без риска по срокам)
1. Избранное (локально), если не требует сервера.
2. Карта точки/адрес (YandexMapView), если не тянет доп. интеграций.
3. Упрощенные бонусы/скидки — только если это purely client‑side и не ломает auth/заказы.

### Out of scope (после релиза)
1. Оплата СБП.
2. Telegram‑бот для бариста.
3. Полная система лояльности, награды/баллы, история заказов на бэке.
4. Глубокая аналитика, A/B, рекомендации.
5. Сложные промо‑механики/кампании.

## 3) Roadmap (критический путь до релиза)
1. Реальный auth по телефону (OTP + валидация + сессии).
2. Backend для заказов и статусов (минимальный, но настоящий).
3. Админка/CRUD меню/промо для контента без релиза.
4. Observability + ошибки (crash/логирование/аналитика ключевых событий).
5. Юридические требования (privacy/terms/account deletion), метаданные, TestFlight.

## 4) Открытые решения (нужно подтвердить)
1. Включаем ли «Избранное» в MVP как purely‑client функциональность?
2. Оставляем ли YandexMapView в MVP или откладываем после релиза?
3. Нужна ли «мини‑лояльность» в MVP, или полностью переносим в post‑release?

## 5) Риски по срокам
- Задержки с OTP‑провайдером и edge‑cases по номерам.
- Отсутствие тестов до поздней стадии.
- Drift по scope.
