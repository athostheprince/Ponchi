# Ponchi

Этот `README` — в первую очередь рабочий план и текущий контракт проекта для меня самой: что уже хорошо, что еще слабое, что находится в активной доработке и какие задачи сейчас приоритетны.

## Текущая цель
- Довести клиент до первого реалистичного MVP.
- Подключить backend в `Yandex Cloud`.
- Перевести auth, user data и orders из локальной модели в реальные серверные сценарии.
- Определить и внедрить `SwiftData` как локальный persistence-слой.
- Подготовить приложение к использованию реальными клиентами кофейни.

## Что уже является сильной стороной проекта

### Продуктовая сторона
- Это не тудушка, а прикладной мобильный сценарий для кофейни: меню, корзина, профиль, заказы.
- Основной UI уже собран, поэтому текущая работа идет не с нуля, а вокруг доведения продукта до реального использования.
- Меню уже загружается из сети и имеет офлайн-фоллбек.
- Проект движется в сторону реальной эксплуатации, а не только красивого демо.

### UI и визуальный характер
- У приложения уже есть свой визуальный язык: фирменная палитра, кастомные шрифты, мягкие формы, glass-style кнопки, кастомный таббар.
- Один из сильных аспектов проекта — анимации и motion: splash-screen, haptic feedback, spring-переходы, интерактивные переключения состояний.
- Особенно удачной частью текущего UI я считаю экран входа и регистрации: там уже есть ощущение отдельного сценария, а не просто набора полей.
- В проекте уже есть авторское ощущение интерфейса, а не стандартный шаблонный iOS-экран.

## Что уже реализовано

### Клиентские сценарии
- `SwiftUI` приложение с основными экранами и кастомным таббаром.
- Меню: категории, поиск, деталка товара, размеры, топпинги, апселл.
- Корзина: добавление, удаление, изменение количества, подсчет суммы.
- Профиль: локальные данные пользователя, редактирование, бонусы, формы входа и регистрации.
- Заказы: локальная модель заказа, активные и завершенные заказы.
- Карта точки через `YandexMapView`, если `YandexMapsMobile` доступен в сборке.

### Данные и состояние
- Загрузка меню из удаленного JSON.
- Локальный фоллбек меню при проблемах с сетью.
- Баннер офлайн-состояния и обработка ошибок загрузки меню.
- Локальное хранение token/session state через `Keychain`.

## Что еще слабое / в доработке

### Backend и данные
- Backend еще в активной разработке в `Yandex Cloud`.
- Схема данных проектируется в `PostgreSQL` через `DBeaver`.
- Меню пока еще не переведено полностью на backend/API и все еще опирается на JSON-источник.
- Реальные заказы пока не подключены: сейчас используется локальная клиентская модель.
- Локальный persistence-слой пока не оформлен системно: нужно определить, что хранится в `SwiftData`, а что должно оставаться только на backend или в `Keychain`.

### Auth / User / Orders
- Реальная аутентификация по номеру телефона еще не завершена.
- Auth-flow с паролем и SMS-кодом пока находится в проектировании и реализации.
- Профиль пользователя пока опирается на локальное состояние и должен перейти к реальным данным и серверным сессиям.
- История заказов и статусы заказов пока еще не backend-driven.

### UI, который еще надо дополировать
- Несмотря на то что визуальный язык в целом уже сильный, экран пользователя пока меня не устраивает в финальном виде и находится в доработке.
- Экран заказов тоже еще не устраивает визуально и по структуре, поэтому UI этого блока тоже остается в активной доработке.
- Избранное еще не доведено ни по UX, ни по визуальной части и тоже считается незавершенным блоком.

## Архитектурное направление
- Клиент: `SwiftUI` + `MVVM`
- Меню постепенно выносится в структуру `UseCase` / `Repository` / `DataSource`
- Источник удаленного меню сейчас конфигурируется в `Ponchi/PonchiApp.swift`
- Локальное хранение планируется выстроить через `SwiftData` для тех сценариев, где нужен устойчивый client-side state
- На стороне backend проектируется API для `auth`, `me`, `menu`, `orders`
